# Plano de Importação

Este documento organiza a importação gradual da base de conhecimento para o Obsidian.

## Objetivo

Importar com controle, sem misturar tipos de conteúdo e sem perder os links originais.

## Princípios

- não importar tudo de uma vez
- não mover conteúdo sem classificação
- não alterar a fonte original no Drive
- preservar links e status
- separar material interno de material público

## Fases sugeridas

### Fase 1 - Inventário

Registrar:
- título
- tipo
- status
- autor
- link original
- observações

### Fase 2 - Estrutura

Criar a pasta base e as notas de índice antes de importar conteúdo.

### Fase 3 - Conteúdo consolidado

Importar primeiro:
- itens `Postado`
- tutoriais já publicados
- playbooks mais usados
- normas e procedimentos centrais

### Fase 4 - Conteúdo de apoio

Importar depois:
- BKPs
- materiais complementares
- referências técnicas
- documentos de contexto

### Fase 5 - Pendências

Tratar os itens `Pendente` separadamente para evitar usar material incompleto como versão final.

### Fase 6 - Revisão e ligação entre notas

Criar links entre:
- índice mestre
- playbooks
- tutoriais
- BKPs
- normas
- relatórios ou documentos relacionados

## Ordem recomendada de importação

1. Índice mestre
2. Documentos mais usados
3. Tutoriais publicados
4. Playbooks internos
5. BKPs e materiais de apoio
6. Pendências

## Critérios para decidir prioridade

Importar primeiro o que:
- é mais usado
- é mais reutilizado
- resolve dúvidas frequentes
- representa processo crítico
- tem impacto recorrente no suporte

## Critérios para segurar a importação

Deixar para depois o que:
- está incompleto
- está duplicado
- não tem link confiável
- ainda depende de validação
- pode confundir conteúdo interno com conteúdo para cliente

## Saída esperada

Ao final da importação gradual, a base deve ter:
- índice mestre funcional
- conteúdo organizado por tipo
- links originais preservados
- materiais internos e externos separados
