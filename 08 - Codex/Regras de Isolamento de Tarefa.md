# Regras de Isolamento de Tarefa

## Regra principal

- Cada tarefa deve ter um objetivo unico e claro.
- Se houver objetivos diferentes, usar sessoes separadas.

## Quando isolar

- Quando a tarefa envolver areas diferentes do vault.
- Quando existir risco de mistura entre contexto tecnico e documental.
- Quando houver tarefas paralelas que possam sobrescrever o mesmo arquivo.
- Quando a resposta depende de confirmacao antes de seguir.

## Como isolar

- Criar uma sessao por objetivo principal.
- Ler apenas os arquivos relevantes daquela tarefa.
- Evitar editar varios temas no mesmo arquivo.
- Registrar checkpoints quando a sessao ficar longa.
- Encerrar a sessao com o proximo passo claro.

## O que nao fazer

- Nao misturar importacao, documentacao e implementacao no mesmo fluxo sem necessidade.
- Nao usar a mesma sessao para tarefas sem relacao direta.
- Nao assumir que a IA vai preservar tudo sem apoio no vault.
- Nao abrir automacoes sensiveis junto com alteracoes documentais.

## Exemplo de isolamento

- Uma sessao para estudar transcricoes.
- Outra sessao para criar notas.
- Outra sessao para criar templates.
- Outra sessao para implementar automacoes aprovadas.

## Resultado esperado

- Menos retrabalho.
- Menos perda de contexto.
- Menos risco de sobrescrever trabalho.
- Historico mais facil de continuar no dia seguinte.
