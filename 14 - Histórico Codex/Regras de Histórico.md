# Regras de Histórico do Codex

Este vault usa histórico de sessão para permitir continuar o trabalho no dia seguinte.

## Pasta principal

Os históricos organizados devem ficar em:

`14 - Histórico Codex/Sessões`

Os logs brutos do terminal ficam em:

`14 - Histórico Codex/Logs Brutos`

## Regra de salvamento

Durante uma sessão de trabalho, o Codex deve criar ou atualizar o arquivo do dia:

`14 - Histórico Codex/Sessões/YYYY-MM-DD.md`

## Quando atualizar

Atualizar o histórico organizado:

1. A cada 10 mensagens enviadas pelo usuário.
2. Quando o usuário escrever `Finalizaar`.
3. Quando o usuário escrever `Finalizar`.
4. Quando houver mudança importante no vault.
5. Antes de encerrar uma etapa grande de importação, organização ou revisão.

## O que registrar

Cada checkpoint deve conter:

- Horário aproximado.
- O que foi feito.
- Arquivos criados.
- Arquivos alterados.
- Decisões tomadas.
- Prompts importantes usados.
- Problemas encontrados.
- Próximos passos recomendados.
- Estado atual do trabalho.
- Onde continuar amanhã.

## Formato do arquivo diário

O arquivo `YYYY-MM-DD.md` deve seguir esta estrutura:

# Histórico Codex - YYYY-MM-DD

## Resumo do dia

## Linha do tempo

## Arquivos criados

## Arquivos alterados

## Decisões importantes

## Problemas encontrados

## Prompts úteis usados

## Estado atual

## Próximos passos

## Como continuar amanhã

## Links internos relevantes

## Observações

## Regra importante

Não registrar senhas, tokens, credenciais, dados sensíveis ou informações privadas de clientes.
