# Benchmark de Referências V2

Data de acesso: 2026-07-29

Escopo: páginas oficiais de Hostinger, Cursor, Sourcegraph, GitBook, Mintlify, Linear, Supabase, Resend, Vercel, Stripe, Raycast e Sentry.

## Síntese

O padrão mais útil para o Legacy Doc é: produto visível na primeira dobra, prova técnica concreta, alternância de composição, relatório/documentação como entregável central e pricing organizado sem promessas extras. A V2 deve se inspirar em Cursor para demonstração de produto, Sourcegraph para codebases complexas, GitBook/Mintlify para documentação, Linear para disciplina visual, Supabase/Resend/Sentry para artefatos de código e Hostinger para organização clara de planos.

## Padrões extraídos

- Heros fortes mostram produto antes de explicar tudo.
- Screenshots e interfaces precisam ocupar largura significativa.
- Código funciona melhor quando conectado a um resultado.
- Pricing deve ser escaneável, mas não deve inventar recursos.
- Seções longas precisam alternar formatos: demo, documento, timeline, matriz e planos.
- Mobile precisa recortar a demonstração por estados, não apenas empilhar todo o desktop.

## Recomendação unificada

V2 deve abrir com um demo técnico grande, depois mostrar transformação, pipeline, screenshots reais, relatório claro, planos oficiais, origem/pesquisa secundária, roadmap, equipe, FAQ e CTA final. A página deve parecer produto real em desenvolvimento, não apresentação acadêmica nem documentação institucional.
