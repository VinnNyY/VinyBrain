# Direcao Visual

Data: 2026-07-29

## Conceito visual escolhido

`Codigo legado complexo -> analise -> identificacao de estrutura -> organizacao de informacoes -> documentacao tecnica clara`

A landing deve mostrar o Legacy Doc como um produto tecnico real que entra em uma base confusa e devolve clareza operacional. A confianca deve vir de evidencias visuais: codigo, arvore de arquivos, grafo tecnico, estados de analise, rastreabilidade e preview de relatorio.

## Personalidade visual

O Legacy Doc deve parecer:

- tecnologico;
- confiavel;
- maduro;
- premium;
- tecnico;
- moderno;
- preparado para evoluir comercialmente.

Nao deve parecer:

- trabalho escolar;
- template generico;
- apresentacao de slides;
- site cyberpunk;
- pagina com particulas;
- colecao de imagens genericas de IA.

## Direcao estetica

- Dark theme como experiencia principal.
- Fundo solido e profundo, sem gradientes dominantes.
- Superficies escuras com bordas sutis e elevacao controlada.
- Azul oficial usado para acao, foco, progresso e estados ativos.
- Mockups devem parecer produto real, nao ilustracao abstrata.
- Tipografia limpa, tecnica e legivel.
- Cards funcionais, densos e alinhados.
- Muito espaco negativo, mas com conteudo tecnico concreto.

## Paleta

Dark theme prioritario:

- Background: `#0b0f19`
- Surface: `#111827`
- Border: `#263244`
- Text: `#ffffff`
- Text secondary: `#94a3b8`
- Primary: `#3b82f6`

Variacoes permitidas:

- Surface muted: `#0f172a`
- Surface raised: `#151f32`
- Code/browser: `#090d15`
- Primary hover: `#60a5fa`
- Primary active: `#2563eb`
- Primary soft: `rgba(59, 130, 246, 0.12)`
- Border soft: `rgba(148, 163, 184, 0.16)`
- Border strong: `rgba(148, 163, 184, 0.28)`

Estados funcionais:

- Success: `#22c55e`
- Warning: `#f59e0b`
- Danger: `#ef4444`
- Info: `#38bdf8`

Uso: essas cores devem ser estados funcionais. Nao usar como paleta decorativa aleatoria.

Light theme secundario:

- Background: `#ffffff`
- Surface: `#f1f5f9`
- Border: `#d1d5db`
- Text: `#000000`
- Text secondary: `#475569`
- Primary: `#2563eb`

## Primeira dobra

A primeira dobra precisa mostrar:

1. O que e o produto: IA para analisar bases legadas ou pouco documentadas.
2. O resultado: documentacao tecnica estruturada.
3. Prova visual: interface realista com codigo, analise e relatorio.

Composicao recomendada:

- Desktop: headline e CTAs a esquerda; mockup de produto a direita.
- Notebook: mesma composicao com mockup menos denso.
- Tablet/mobile: copy primeiro, mockup em seguida, sem miniaturizar detalhes ilegiveis.

## Prova visual principal

O mockup principal deve combinar:

- sidebar de arquivos/modulos;
- painel central de analise;
- painel de documentacao gerada;
- indicadores de processamento;
- badges de status;
- pequenos vinculos de rastreabilidade.

Exemplos de conteudo visual:

- `src/auth`
- `billing`
- `legacy-api`
- `jobs/sync`
- `database`
- `Architecture mapped`
- `Risk pending review`
- `Generated documentation`
- `Based on src/billing/InvoiceService`

## Secao de relatorio

A secao de relatorio deve ser uma ancora visual da pagina.

Ela deve parecer o entregavel real do produto, com:

- indice lateral;
- resumo do sistema;
- arquitetura detectada;
- modulos principais;
- fluxos criticos;
- dependencias externas;
- riscos e pontos de atencao;
- lacunas de documentacao;
- evidencias no codigo;
- perguntas para validacao tecnica.

Essa secao nao deve ser apenas um card com promessa. Deve parecer um documento tecnico premium, revisavel e operacional.

## Linguagem visual

Usar:

- blocos de codigo;
- navegadores simulados;
- tabelas compactas;
- badges tecnicos;
- tabs;
- grafo tecnico simples;
- linhas de conexao discretas;
- cards de findings;
- preview de relatorio.

Evitar:

- fotos genericas de escritorio;
- pessoas olhando notebook;
- ilustracoes 3D aleatorias;
- terminais "hacker";
- neon;
- cyberpunk;
- particulas;
- orbs;
- glassmorphism pesado;
- roxo dominante;
- mockups ilegiveis;
- dashboard falso sem relacao com documentacao.

## Referencias de nivel

Usar apenas como nivel de qualidade e experiencia:

- Linear: rigor, densidade e acabamento.
- Vercel: clareza, performance visual e composicao tecnica.
- GitHub: familiaridade com codigo, repositorios e dev tools.
- Raycast: polimento, comando e precisao.
- Resend: copy tecnica contida e exemplos visuais.
- Supabase: produto tecnico com interface demonstravel.
- Stripe: confianca, hierarquia e materialidade.
- Framer: acabamento visual e motion controlado.
- Cursor: produto de desenvolvimento com IA.
- Sourcegraph: contexto de codebase e ferramenta de engenharia.

Nao copiar paginas, componentes, textos ou layouts.

## Riscos

- Parecer generico se os mockups nao mostrarem codigo e documentacao reais.
- Parecer academico se a pesquisa/TCC ganhar peso visual excessivo.
- Parecer IA generica se houver imagem abstrata em vez de interface.
- Parecer cyberpunk se houver neon, grid e particulas.
- Perder confianca se a pagina prometer seguranca, compatibilidade ou acuracia sem evidencia.
