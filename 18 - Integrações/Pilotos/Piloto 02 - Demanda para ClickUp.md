# Piloto 02 - Demanda para ClickUp

## Objetivo do piloto

Este piloto serve para transformar pedidos, ideias, pendências ou demandas soltas em tarefas claras para o `ClickUp`, com registro mínimo no `Viny Brain` e documentação opcional no `Notion`.

## Entrada bruta

Cole aqui a demanda do jeito que chegou.

```txt
Origem:
Solicitante:
Contexto:
Demanda:
Prazo desejado:
Responsável sugerido:
Prioridade percebida:
Observações:
Links úteis:
```

## Análise da demanda

Preencha estes campos antes de decidir se a demanda vira tarefa.

```txt
Tipo da demanda:
Área afetada:
Urgência:
Impacto:
Esforço estimado:
Dependências:
Riscos:
Precisa virar tarefa:
Precisa virar documentação:
Precisa virar decisão no Viny Brain:
```

## Leitura rápida

- Tipo de demanda:
- Área afetada:
- Urgência:
- Impacto:
- Esforço estimado:
- Risco ou atenção:

```txt
- [ ]
- [ ]
- [ ]

```

## Checklist da tarefa

Use este modelo para decompor a execução.

```txt
- Entender demanda
- Validar contexto
- Executar ação
- Testar ou validar
- Registrar evidência, se necessário
- Comunicar conclusão
- Atualizar status
```

## Registro mínimo no Viny Brain

Use este bloco para guardar apenas o essencial.

```txt
Demanda:
Decisão:
Motivo:
Responsável:
Status:
Próximo passo:
Link da tarefa no ClickUp:
```

## Quando mandar para Notion também

Envie para Notion apenas se a demanda:

- virar projeto;
- precisar de documentação;
- envolver reunião;
- envolver decisão importante;
- precisar ser compartilhada com gestão;
- tiver histórico relevante.


## Critério de envio para cada ferramenta

- `Viny Brain`: sempre recebe um registro mínimo da decisão e do contexto.
- `ClickUp`: recebe a tarefa quando a demanda já estiver clara e executável.
- `Notion`: recebe documentação opcional quando a demanda precisar de visibilidade ou explicação maior.

## Fonte da verdade

- `Viny Brain`: contexto, decisão, risco e histórico.
- `ClickUp`: execução, acompanhamento e status.
- `Notion`: leitura compartilhável, quando necessário.

## Checklist de segurança

- [ ] Não contém senha
- [ ] Não contém token
- [ ] Não contém dados sensíveis de cliente
- [ ] Não contém acesso interno
- [ ] Não contém print sensível
- [ ] Pode virar tarefa no ClickUp
- [ ] Pode ser registrado no Viny Brain

## Checklist final do piloto

- [ ] Tarefa ficou clara
- [ ] Responsável está definido ou marcado como pendente
- [ ] Prazo está definido ou marcado como pendente
- [ ] Prioridade está coerente
- [ ] Checklist está acionável
- [ ] Fonte da verdade ficou clara
- [ ] Não houve duplicidade desnecessária

## Como usar o piloto

1. Cole a demanda bruta.
2. Preencha a análise da demanda.
3. Confirme se a demanda vira tarefa, documentação ou decisão.
4. Copie a saída para o ClickUp quando estiver pronta.
5. Registre o essencial no `Viny Brain`.
6. Use o bloco de Notion apenas quando a regra permitir.

## Observações de segurança

- Não registrar tokens, senhas, IPs sensíveis ou dados reais de cliente.
- Se a demanda ainda estiver nebulosa, manter só no `Viny Brain`.
- Não transformar demanda em tarefa real sem revisão manual.
- Este arquivo é apenas um modelo copiável.

## Prompt reutilizável

`Use este piloto como modelo manual. Leia a demanda solta, analise tipo, área afetada, urgência, impacto, esforço, dependências e riscos, decida se vira tarefa, documentação ou decisão, prepare uma tarefa pronta para o ClickUp, registre o mínimo no Viny Brain e use Notion só quando a regra permitir, sem conectar APIs, sem criar nada automaticamente e sem registrar dados sensíveis.`
