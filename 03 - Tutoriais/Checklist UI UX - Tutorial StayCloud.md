# Checklist UI UX - Tutorial StayCloud

## Objetivo

Validar clareza, fluxo, prints, marcações visuais, acessibilidade, risco e facilidade de execução de um tutorial StayCloud antes da revisão final.

## Quando usar

- antes do checklist final;
- depois de revisar texto e prints;
- antes de seguir para WordPress;
- quando houver duvida sobre friccao, leitura ou jornada do cliente;
- quando o material visual precisar de validacao de experiencia.
- quando for preciso confirmar se um cliente leigo consegue seguir sem ajuda.

## Quando nao usar

- para alterar layout real;
- para publicar conteudo;
- para instalar plugin;
- para mexer em WordPress;
- para editar painel real sem autorizacao;
- para substituir revisao de SEO ou revisao de seguranca.

## Clareza

- [ ] O cliente entende o objetivo em ate 5 segundos
- [ ] O tutorial deixa claro para quem e
- [ ] O titulo corresponde ao problema real
- [ ] A introducao explica o beneficio sem enrolacao
- [ ] A linguagem esta simples e direta
- [ ] O texto fala com o leitor em tom público, sem linguagem interna

## Fluxo

- [ ] Os passos estao em ordem logica
- [ ] Nao pula etapa
- [ ] Mostra onde clicar
- [ ] Diferencia painel novo vs painel antigo quando necessario
- [ ] O cliente consegue seguir sem adivinhar a proxima acao

## Prints

- [ ] Os prints estao legiveis
- [ ] Os prints mostram contexto suficiente
- [ ] Nao ha dados sensiveis expostos
- [ ] Nao ha pop-ups desnecessarios
- [ ] O recorte esta correto
- [ ] As marcacoes visuais ajudam sem poluir
- [ ] O clique, campo ou área importante está desenhado no print
- [ ] Nao ha placeholder de print em tutorial final
- [ ] O contraste permite leitura
- [ ] A imagem nao esta carregada ou confusa

## Marcas visuais

- [ ] Ha seta, contorno ou destaque quando necessario
- [ ] As marcacoes nao escondem o elemento principal
- [ ] Nao ha excesso de marcações
- [ ] A imagem continua limpa e objetiva

## Experiencia do cliente

- [ ] O cliente sabe o que fazer se der erro
- [ ] Existe aviso de risco quando necessario
- [ ] Existe alternativa quando o caminho nao aparece
- [ ] Existe orientacao sobre quando abrir ticket
- [ ] O tutorial reduz chance de ticket repetido
- [ ] O tutorial antecipa duvidas comuns
- [ ] Um cliente leigo conseguiria seguir sem travar

## Acessibilidade

- [ ] As frases sao curtas
- [ ] A linguagem e simples
- [ ] Nao depende so do print para entender
- [ ] As imagens tem contexto textual
- [ ] Nao ha jargao desnecessario

## Risco e suporte

- [ ] Nao promete mais do que entrega
- [ ] Nao orienta acao tecnica arriscada sem aviso
- [ ] Nao expoe dados sensiveis
- [ ] Nao confunde painel novo com painel antigo
- [ ] Existe indicacao de quando chamar suporte

## SEO e clareza

- [ ] O SEO nao prejudica a clareza
- [ ] A palavra-chave nao deixa o texto artificial
- [ ] O titulo continua natural para o cliente
- [ ] A meta description nao sacrifica entendimento
- [ ] Os textos dos prints e legendas também seguem tom de cliente final

## Decisao

- [ ] Aprovado
- [ ] Aprovado com ajustes
- [ ] Reprovado

## Ajustes obrigatorios

- [ ] Novo print necessario
- [ ] Texto precisa simplificar
- [ ] Fluxo precisa reorganizar
- [ ] Marcações precisam melhorar
- [ ] Aviso de risco precisa entrar
- [ ] Seção de ticket precisa aparecer
- [ ] Tutorial precisa ser reprovado por falta de marcação visual obrigatória

## Dados sensíveis nos prints

- [ ] Cada print foi inspecionado em tamanho ampliado.
- [ ] Não há e-mail, IP, nome, documento, telefone, endereço, domínio identificável, credencial ou ID de cliente visível.
- [ ] Havendo dado sensível, existe cópia sanitizada em `prints/finais/`.
- [ ] O original está isolado e não é referenciado pelo tutorial, modelos aprovados ou WordPress.
- [ ] A censura é opaca, completa e não cobre a ação ensinada.

## Alvo das marcações visuais

- [ ] Cada marcação aponta exatamente para o elemento citado no texto.
- [ ] O passo seguinte confirma que o alvo leva ao fluxo correto.
- [ ] Não há destaque em botão próximo, banner, alerta, fatura ou ação alternativa.
- [ ] Cada etapa simples possui apenas um alvo principal.
- [ ] A marcação não cobre botão, campo, menu, filtro, título ou texto necessário.
- [ ] A legenda e o ALT text descrevem o mesmo alvo marcado.
- [ ] A URL pública da imagem corresponde ao print local final aprovado.
